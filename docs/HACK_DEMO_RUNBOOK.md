# HACK-DEMO v2 — Operator runbook

Use with the [2:50 script](HACK_DEMO.md). These are **planned calls**, checked against merged source, not a record of executed production actions. Rehearse once through the real browser tools and update [the handoff](HACK_DEMO_STATE.md) with observed outcomes.

## Operator conventions

- Two genuine sessions: **Team** (workspace creator/owner and project lead) and **Client** (external participant with role `approver`). An internal client-account record is not a login or external participant.
- The JSON blocks below show a tool name and its input. They are reference sequences, not batch-execution commands. Execute each call separately, inspect the result, retain returned IDs, and complete required human steps before continuing.
- After the registration compatibility fix is deployed, **before each different business tool**, call `discover_workflows` with `{"load":"<exact tool name>"}`, refresh native browser tools, and then execute that tool. These repeated load steps are implicit in the sequences below. Consecutive actions on the same loaded workflow need no reload. `list_my_work`, `search_work_items`, `get_commercial_drift`, `create_work_item`, discovery, navigation and handoffs remain registered. A query-only discovery call lists flows but does not load one. Never represent the old 59-tool badge as proof that native execution is available.
- Replace `<...Id>` placeholders with IDs returned by authorized reads in the correct session. Workflow results wrap payloads under `data`; a nested object ID is not necessarily the top-level ID. Do not show these IDs in the video.
- `workspace_setup.create` navigates to the new workspace. Wait for that document, then rediscover its tools. Client tools exist on the client surface. Never reuse an old document's tool handle across navigation or login changes.
- Omitted `idempotencyKey` and `revisionIdempotencyKey` values are generated by the adapter; comments/notes also receive `requestId` where required. For a resumable take, supply and retain one explicit UUID per logical write. Never blindly repeat an uncertain create, including the original `create_work_item` shortcut.
- **Review agent action** is a real human confirmation. `human_step_required`, `not_applied`, `outcome_unknown`, `rejected` and `invalid_input` are not success. Inspect current state after interruption; do not fill a caller-supplied confirmation flag or invent a successful response.
